# Telegram Funnel 🐾

Небольшая воронка регистрации: **aiogram 3 + FastAPI + SQLite + YAML + HTML/CSS/JS**. Всё в одном репозитории, без Docker, облачной БД, платных сервисов и отдельного фронтенд-сборщика.

## Что реализовано

- `/start` → приветствие с кнопкой **«Поделиться номером»**.
- Приём **только собственного** Telegram-контакта, защита от передачи чужого номера.
- Сохранение регистрации в SQLite. Повторная отправка номера не создаёт повторные задания.
- **Два сообщения** через **10 и 60 секунд после регистрации**. Тексты и время в `config.yaml`.
- Планировщик проверяет SQLite-очередь раз в секунду; после перезапуска ещё не отправленные сообщения остаются в очереди.
- Дашборд: пользователи, регистрации, конверсия, количество `/start`, отправки, очередь, ошибки, график по дням и последние регистрации.
- Проверка подписи `Telegram.WebApp.initData` + проверка ID администратора для доступа к статистике.
- Дополнительный вход в дашборд по паролю из `.env` (`DASHBOARD_PASSWORD`), защищённая HttpOnly-cookie сессия, ограничение попыток и кнопка выхода. До авторизации статистика скрыта.
- Локальный предпросмотр панели в браузере без Telegram.

## Запуск на Windows / PowerShell

Требуется **Python 3.11+** и токен бота от [@BotFather](https://t.me/BotFather).

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` заполнить:

```dotenv
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=ваш_telegram_numeric_id
WEB_HOST=127.0.0.1
WEB_PORT=8000
DASHBOARD_PREVIEW=1
MINI_APP_URL=
DASHBOARD_PASSWORD=
```

Затем:

```powershell
python -m app.main
```

1. В Telegram открыть своего бота и отправить `/start`.
2. Нажать **«Поделиться номером»**.
3. Через 10 и 60 секунд придут сообщения (отсчёт от регистрации).
4. Открыть браузер: **http://127.0.0.1:8000** — локальная статистика.

## Настройка текстов и таймингов

Редактировать `config.yaml`:

```yaml
messages:
  - delay_seconds: 10
    text: "Первое сообщение"
  - delay_seconds: 60
    text: "Второе сообщение"
```

Для применения новых текстов и задержек **перезапустить приложение**. Уже созданные в базе задания сохраняют первоначальные тексты и сроки, чтобы не изменять существующую очередь.

## Как именно открыть Mini App в Telegram

**Ограничение Telegram:** веб-приложение внутри Telegram требует **публичный HTTPS URL**. Адрес `localhost` Telegram не сможет открыть как Mini App. Для тестового задания ничего деплоить не нужно: локальный дашборд работает в браузере. Если нужно продемонстрировать именно встроенный Telegram Mini App, можно временно пробросить локальный `localhost:8000` через HTTPS-туннель (например, ngrok / cloudflared), затем:

1. Указать полученный адрес `https://...` в `MINI_APP_URL` внутри `.env`.
2. **Обязательно** установить `DASHBOARD_PREVIEW=0`, чтобы включилась авторизация.
3. Перезапустить процесс и отправить `/start` от администратора (`ADMIN_IDS`).
4. Открыть кнопку **«📊 Статистика»** в Telegram.

Важно: не публикуйте сервер с `DASHBOARD_PREVIEW=1`. Предпросмотр разрешён только на loopback-интерфейсе, и API без авторизации открыт **только локально**.

## Вход в дашборд по паролю

Чтобы включить альтернативный вход (когда Telegram initData не передаётся), установите в `.env` переменную `DASHBOARD_PASSWORD` со **сложным уникальным паролем**. Пароль `123` недопустим для публичного сайта: его можно использовать только в изолированном локальном окружении. После правки `.env` перезапустите приложение.

При `DASHBOARD_PREVIEW=0` статистика доступна либо администратору с валидным Telegram `initData`, либо после входа по паролю. Пока вход не выполнен, страница отображает форму авторизации вместо статистики. Cookie имеет ограниченное время действия, устанавливается как HttpOnly и Secure (для HTTPS).

## Известные ограничения

- Доставка запланированных сообщений осуществляется при работающем процессе; во время остановки сообщения ждут в БД и отправляются после следующего запуска.
- При аварийной остановке **в момент успешного Telegram API запроса**, но до обновления БД, возможна повторная отправка: Telegram Bot API не даёт полноценной идемпотентности отправки. Для тестового этого достаточно.
- Ошибки доставки помечаются как `failed`, без автоматического повтора (во избежание спама и дублей). В панели виден счётчик ошибок.
- Сервис рассчитан на **один запущенный процесс**, без горизонтального масштабирования.
- Телефоны хранятся в локальной БД, в API статистики они **не отдаются**. Не добавляйте `data/` и `.env` в Git (уже исключены через `.gitignore`).
